Dependency Management
Dependency = งานที่ต้องรอ task อื่นก่อนถึงจะทำได้ — ต้องระบุตั้งแต่ Task Breakdown
ตัวอย่าง dependency chain
Payroll Disburse
└── รอ DisbursementService [BE] ← dependency
    └── รอ WalletService.bulkCredit [BE]
        └── รอ KYC verified [Infra]
Stepสิ่งที่ต้องทำ
Task Breakdownระบุ dependency ทุก task — "รอ task ไหนก่อน"
Task Creationลิงก์ dependency ใน ClickUp (depends on field)
Work Executionถ้า dependency ยังไม่พร้อม → Blocked ทันที
Escalationdependency cross-team → PL นำเข้า Cross-Team Meeting
กฎ: dependency cross-team ต้องแจ้ง PL ภายใน 24h — ไม่รอให้กระทบ deadline
TL Delegation Rule
TL ตัดสินใจเองได้ โดยไม่ต้องรอ PL — ถ้าไม่กระทบ Scope / Timeline / Budget
DecisionTL ตัดสินได้เองต้องแจ้ง
Technical approach✓ ตัดสินได้—
Code quality standard✓ ตัดสินได้—
SP estimate✓ ตัดสินได้—
Re-assign ภายใน team✓ (แจ้ง PL ทราบ)แจ้ง PL ทราบ
Scope change✗ ต้องแจ้ง PLPL final
Timeline change✗ ต้องแจ้ง PLPL final
Budget / resource✗ ต้องแจ้ง COOCOO final
Architecture change✗ ต้องแจ้ง CTOCTO final
เป้าหมาย: TL ทำงานได้เร็วขึ้น PL ไม่เป็น bottleneck — ทีม scale ได้ถึง 30–50 คน
Closing Tier Standard
PL กำหนด closing tier ตั้งแต่ Work Intake — ทุกคนรู้ตั้งแต่ต้นว่าต้องทำอะไรก่อน Done
Tierตัวอย่างClosing Requirement
Normal bug fix, text change, UI tweak QA sign-off
Major new feature, workflow change QA sign-off + Demo
Business Critical financial, payment, consent QA + Demo + PO Signoff
Hotfix production incident, critical bug QA + PL Approval (fast track)
กฎ: PL กำหนด tier ตอน Work Intake ถ้าไม่แน่ใจ → default เป็น Major ไว้ก่อน ดีกว่า under-tier
